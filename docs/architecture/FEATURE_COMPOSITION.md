# 功能组合与代码裁剪

AIForge 将“业务功能选择”和“运行环境配置”分成两个阶段：

```text
npm create aiforge → 选择业务功能、组合代码
pnpm run setup     → 配置端口、PostgreSQL、项目密钥和管理员
后台服务配置        → 配置邮件、短信、Redis、对象存储、Git 和服务器
```

## 分层

### 核心内核

Admin、API、PostgreSQL + Prisma、管理员认证、管理员管理、角色权限、操作日志、系统信息、服务资源、对象存储资源库、部署中心、Deploy Worker、错误处理和健康检查始终存在。

### 用户可选业务功能

| 功能 ID       | 用户结果                                                          | 自动依赖 |
| ------------- | ----------------------------------------------------------------- | -------- |
| `customerWeb` | Nuxt 用户端、账号、验证码认证、会话、个人中心、头像和后台用户管理 | 无       |

### 共享能力

邮件、短信、Redis、验证码和消息模板不是 CLI 业务选项，启用用户端时由依赖图自动保留。对象存储资源库、Git、SSH 和部署能力属于核心平台能力，始终存在；运行时再绑定具体服务资源。

### 服务商适配器

SMTP、腾讯云 SES、腾讯云短信、COS、Redis、Git 和 Linux 服务器只负责连接外部系统，不决定项目是否拥有业务功能。服务商与密钥在项目生成后通过后台服务配置维护。

## 唯一归属规则

- 一个可裁剪路径只能由一个功能拥有。
- 多功能共用的代码必须登记为共享能力，不允许复制到多个功能目录。
- 页面、路由、API 模块、权限、Prisma 模型、环境变量和测试必须能追溯到核心或一个功能。
- `project.config.json.features` 是业务选择事实来源；`modules` 只能由功能依赖图生成。
- CLI 只允许选择是否启用 `customerWeb`；禁止直接让用户选择 `customerAvatar`、`deploymentCenter`、`email`、`sms`、`redis` 或 `objectStorage`。
- 新功能先登记功能目录及依赖，再实现代码。

`pnpm feature:check` 检查依赖闭包、模块推导、路径唯一归属和应用裁剪结果。发布前至少验证：基础平台，以及基础平台 + 用户端两种组合。

## 维护者与使用者

模板维护者从 GitHub 获取完整代码，普通用户通过 CLI 获取裁剪代码。两者之后统一执行 `pnpm install`、`pnpm run setup`、`pnpm doctor` 和 `pnpm dev`，不维护专用环境文件或第二套初始化逻辑。
