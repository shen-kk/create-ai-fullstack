# 全栈工程规范

本文件只记录 Admin、Web、API 共同遵守的规则。视觉与基础组件不跨端共享，分别以 `docs/admin` 和 `docs/web` 为准。

## 共同边界

- API 是业务规则、鉴权和持久化的唯一权威来源；前端只通过公开 API 获取数据。
- 跨端请求、响应、分页结构、稳定错误码放在 `packages/contracts`，不得导出数据库或 UI 类型。
- 默认语言为中文；API 保留稳定英文状态码，客户端负责中文映射。
- 所有外部输入在系统边界校验；错误响应不得暴露堆栈、SQL、密钥或第三方原始响应。
- 新功能不得依赖假数据、内存回退或只存在于页面中的业务规则。
- 环境差异通过配置表达，真实密钥不进入 Git、日志、截图和文档。

## 代码原则

- TypeScript 严格模式，不使用无解释的 `any`、`@ts-ignore` 和非空断言。
- 优先复用明确的公共能力，不为未被需求证明的场景提前抽象。
- 单个函数只承担一个清晰职责；页面和 Controller 负责组合，不堆积业务规则。
- 状态、金额、权限、库存和并发写入必须显式校验并具有失败路径测试。
- 时间统一传输 ISO 8601 UTC 字符串，展示层再按用户时区格式化。

## 允许改进规范

规范是当前默认最佳实践，不是不可改变的限制。现有方案不适用时，AI 必须给出问题证据、方案比较、影响范围和迁移计划。局部例外或全局替换应记录 ADR；验证后的更优实现应更新规范并逐步迁移旧实现。
