# 新功能开发流程

所有新功能都按本流程执行。任务只涉及单端时可以跳过无关实现，但不能跳过影响分析。

## 1. 需求与边界

- 用一句话描述用户结果，不以“新增一个页面”代替业务目标。
- 明确角色、权限、数据范围、成功条件、失败场景和不包含内容。
- 检查 `project.config.json` 与 `docs/ai/PROJECT.md`，确认相关能力已启用。
- 搜索已有领域、契约、API、组件和页面模式。

## 2. 设计顺序

1. 领域词汇和状态流转；
2. 共享契约、错误码与权限代码；
3. API 用例、数据模型、迁移和审计；
4. Admin 管理能力；
5. Web 用户流程；
6. 测试、文档和初始化能力声明。

不是所有功能都需要五层实现。例如纯后台配置不需要 Web 页面，但必须明确写出“不影响 Web”。

## 3. 前端设计检查

- 先查对应端的组件清单和页面模式，Admin 与 Web 不相互复制 UI。
- 处理加载、空态、错误、无权限、成功、重复提交和弱网状态。
- 使用稳定错误码映射中文提示，并给出可执行的下一步。
- 组件不适用时先比较“复用、扩展、替换”，必要时记录 ADR。

## 4. 完成定义

- 契约、API、权限、客户端、测试和文档同步完成。
- 数据库变更具有 Prisma migration；公共 API 已更新 OpenAPI。
- 新配置已进入 `.env.example`；敏感值不在仓库中。
- 执行 `pnpm ui:check`、相关测试和 `pnpm check`。
- 更新仍然有效的 AI 上下文，不把临时调试过程写入 `CONTEXT.md`。
