# 模板完善路线图

目标不是堆积演示页面，而是形成一个可直接复制、能被 AI 持续理解、具备真实工程闭环的全栈模板。

## 第一阶段：核心身份与权限

- [x] 管理员登录、退出、刷新会话和获取当前身份（内存/Prisma 身份仓库可切换）
- [x] 密码安全哈希、登录限流和统一稳定错误结构（当前限流器为单实例内存实现，生产环境切换 Redis）
- [x] 用户、角色、权限、刷新会话与审计日志的数据模型和初始迁移
- [x] RBAC 服务端装饰器与守卫基线；前端权限只用于体验优化
- [x] 后台登录页、会话恢复和受保护路由
- [x] 用户创建、基本资料编辑、状态变更、角色分配和前端重复提交保护；管理员使用停用而非删除的生命周期策略
- [x] 菜单/操作权限分层、角色创建编辑、系统角色保护；角色不删除、权限目录随代码发布的生命周期策略
- [x] 用户敏感写操作审计日志、请求 ID 关联、只读后台列表、服务端分页与组合筛选

默认身份基线：单租户起步；短期 JWT Access Token + HttpOnly Refresh Cookie；结构保留未来多租户扩展点。身份模型落地前必须建立 ADR。

## 第二阶段：服务端工程基础

- [ ] Prisma schema、迁移和 DatabaseModule 已完成；用户查询、认证权限和刷新会话已支持显式切换 Prisma，待数据库集成验证
- [ ] 幂等开发种子脚本已完成；待 PostgreSQL 环境执行验证
- [x] 统一异常过滤器与稳定 API 错误结构
- [x] 环境变量启动校验（生产密钥、数据库、来源和端口）
- [x] 请求 ID、结构化 HTTP 日志与审计关联
- [x] `/health/live` 与 `/health/ready` 分离
- [x] OpenAPI Bearer/Cookie 安全方案、模块标签及共享契约权威策略（ADR-0005）；外部 SDK 生成按具体项目需要启用
- [x] 分页、稳定排序、筛选与字段白名单公共约定

## 第三阶段：应用体验

- [x] Admin 通用布局、面包屑、真实身份展示、退出、权限菜单和 404/403 页面
- [x] 移除行业业务占位菜单与静态演示指标；工作台使用真实 API 数据并提供可用入口，系统信息页只展示非敏感运行摘要
- [x] 统一侧边栏线性图标、菜单分组和自定义选择器；个人中心支持资料、头像地址与密码修改
- [x] 后台管理员改用唯一手机号创建与登录，邮箱作为可选联系资料
- [x] 服务配置中心覆盖对象存储、SQL、Redis、短信、邮件和支付，密钥加密存储且不回显
- [x] Admin 表格、表单、确认弹窗和反馈模式
- [ ] Web 首页、登录、注册/激活策略与个人中心（明确移至下一版本，不属于当前冻结范围）
- [ ] SSR 请求封装、SEO 元信息和错误页（下一版本）
- [x] 响应式布局与基础无障碍基线（语义标签、可见焦点、ARIA 状态与移动端布局）

模板只提供通用能力，不预置商城、工单、CMS 等特定行业业务。

## 第四阶段：质量与交付

- [ ] API、共享契约与 Admin 会话单元测试、内存模式关键 HTTP 端到端链路已完成；PostgreSQL 集成和浏览器级端到端测试待完成
- [ ] PostgreSQL 测试数据库隔离
- [ ] PostgreSQL 开发 Compose 与 Admin/API 生产镜像已定义并进入 CI 构建；本机无 Docker，待 CI/有 Docker 环境完成实际镜像验证
- [x] GitHub CI：依赖安装、Prisma 生成、Lint、类型、单元测试、构建、模板干净目录验收和 API E2E
- [x] 环境变量、安全、备份与部署文档
- [x] `pnpm check`、`pnpm test:e2e`、`template:verify` 和 Windows 启动安全检查全量通过
- [x] Windows 重复启动、旧服务替换与健康检查已验证；macOS/Linux 使用跨平台 `pnpm dev:local`，增强型旧进程替换仅限 Windows

## 第五阶段：模板产品化

只有前四阶段验收通过后才进入此阶段：

- [ ] 创建 Git 模板仓库和版本标签
- [x] 示例品牌、固定日期和不可复用业务数据已清理或纳入初始化替换
- [x] 编写 Git 仓库内初始化 CLI：模式、项目名、端口、数据库、管理员和基础设施能力
- [ ] 初始化后已生成品牌/能力运行文件、`.env`、AI 项目记忆、包命名空间替换和显式数据库部署命令；`template:verify --full` 覆盖全新目录依赖安装与构建，启动验收待完成
- [x] 创建并验证仓库内可分发的 Codex 项目模板 Skill：`skills/create-admin-project`
- [x] Skill 引导 Git 创建、初始化选择、AI 项目上下文、数据库确认与首次领域建模流程
- [x] 已通过全新临时目录的 quick 初始化、Doctor、敏感信息隔离、命名空间替换、依赖安装、Prisma Client 生成、测试与生产构建

## 模板冻结标准

- 从空数据库可以通过文档完成启动。
- Admin 与 API 能独立构建和运行；Web 用户端从当前版本冻结标准移除，下一版本单独验收。
- 登录、权限拒绝、用户管理和审计形成完整链路。
- 关键失败路径有自动化测试。
- 不依赖聊天记录即可由 `AGENTS.md` 和 `docs/ai/CONTEXT.md` 恢复上下文。
- 新项目初始化后不残留模板品牌或示例密钥。
