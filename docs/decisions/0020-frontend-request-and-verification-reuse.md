# ADR-0020：前端请求与验证码流程收口

## 决策

- Admin 业务 API 统一使用 `api/request.ts`，负责鉴权头、超时、稳定错误码、204 和一次 401 刷新重试；会话模块继续独立负责登录与刷新，避免循环依赖。部署保留 20 秒超时，头像保留 30 秒，SSE 保留调用方取消控制。
- 同时失败的请求共用一次刷新；已更新令牌的迟到 401 直接重试，避免再次轮换会话。
- Web 保持独立请求层及 Nuxt 状态隔离，不创建跨应用 UI 或认证抽象。原生 AbortSignal 负责请求超时。
- 登录、找回密码、绑定邮箱复用验证码发送 composable，发送开始时固定目标，避免请求期间修改输入把倒计时绑定到错误账号。
- 删除不再展示的页面状态及重复赋值，保留现有布局、文案语义和 SSR。公共组件、页面布局与样式只在有明确重复或缺陷时调整，不为减少行数合并业务边界。
- Admin 历史弹窗全部复用现有 AppDialog，外层使用原生 dialog 的模态、焦点约束与 Escape 事件；继续保留自定义视觉、固定头尾和禁止遮罩关闭规则。

## 验证

覆盖并发刷新、迟到 401、204、上传头、错误状态、倒计时与重复提交，并执行两端 Lint、类型检查、测试和生产构建。
