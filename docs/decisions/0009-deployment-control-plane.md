# ADR-0009：本地引导与远程部署控制面

## 状态

已接受。

## 背景

模板使用者需要在后台创建多个开发、测试、预发布或生产部署环境，并按初始化时启用的 Admin、API、Web 应用一键发布。项目第一次尚未上线时只能由本机执行；首次发布后，管理员必须能够从远程后台继续构建、部署和回滚，且生产服务器不承担源码编译。

## 决策

- `template:init` 决定项目具备的应用能力；部署环境只能从已启用的 Admin、API、Web 中选择，可创建任意多个环境。
- 首次发布由仅监听本机的 Deploy Worker 引导，安装 Admin、API、独立 Deploy Agent 与按需启用的 Web/Caddy。成功后控制权移交给远程后台。
- 后续发布由 Admin 请求 API 创建持久化部署任务；独立 Deploy Agent 执行远程切换，API 或 Admin 自身重启不得中断任务。
- 构建默认通过 CNB `api_trigger_deploy` 完成并推送不可变 Commit 标签镜像；目标服务器只拉取镜像、执行待处理迁移、切换容器和健康检查。
- 数据库迁移仅在目标版本包含尚未应用的 Prisma migration 时执行。首次初始化、数据种子与日常迁移是不同操作，日常部署不得重置管理员或重复执行初始化种子。
- 部署目标、任务、步骤与脱敏日志持久化到 PostgreSQL。SSH、CNB、Registry 等秘密使用 `CONFIG_ENCRYPTION_KEY` 加密，API 永不回显明文。
- 自动 HTTPS 使用 Caddy，前提是域名已解析到服务器且 80/443 可用；第一版不代替用户修改 DNS。
- 部署查看、配置和执行使用独立权限；生产部署、回滚和部署组件升级必须审计。

## 结果

部署中心是项目内的控制面，而不是前端直接执行系统命令。首次部署仍可在项目未上线时完成，后续不依赖开发者电脑；构建消耗留在 CNB，生产服务器保持轻量。Deploy Agent 的自升级需要独立接管流程，不与普通应用发布混合。
