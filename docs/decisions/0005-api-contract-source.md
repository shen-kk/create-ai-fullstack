# ADR-0005：共享契约与 OpenAPI 的职责边界

- 状态：已接受
- 日期：2026-08-02

## 背景

Admin 与 API 位于同一 TypeScript 工作区，同时 API 还通过 Swagger 提供可交互文档。若同时将手写 TypeScript、OpenAPI 生成类型和页面局部类型作为权威来源，会产生重复模型和版本漂移。

## 决策

- `packages/contracts` 是仓库内请求、响应与权限目录的类型权威来源。
- API 控制器使用共享契约描述返回类型，边界输入继续使用带运行时校验的 DTO。
- OpenAPI 用于接口发现、鉴权说明、模块分组和外部接入文档；当前模板版本不从 OpenAPI 反向生成内部客户端。
- 面向仓库外部发布 SDK 时，再增加 OpenAPI 响应 Schema 完整性门禁与客户端生成流程；生成代码不得反向成为服务端业务模型。
- 公共契约发生不兼容变化时必须同步更新 API、Admin、测试与版本说明，不允许页面自行复制接口类型。

## 结果

- 当前单仓库只有一个共享类型来源，初始化时包命名空间会一起替换。
- 避免在模板尚未发布外部 SDK 前维护两套等价类型。
- Swagger 仍然是运行接口文档，但不能替代输入校验和共享契约测试。
