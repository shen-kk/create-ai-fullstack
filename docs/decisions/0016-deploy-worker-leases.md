# ADR 0016：Deploy Worker 数据库租约与在线门禁

## 状态

已接受。

## 决策

Deploy Worker 使用数据库租约领取任务。活动任务记录 `workerId`、领取时间、心跳时间、租约过期时间和执行次数；Worker 只有在仍持有有效租约时才能推进步骤或完成任务。独立 Worker 同时登记进程心跳，API 和 Admin 以最近 30 秒内的心跳判断是否在线；没有在线 Worker 时拒绝创建部署或回滚任务。

数据库使用部分唯一索引保证每个环境最多存在一个 `QUEUED`、`RUNNING` 或 `ROLLING_BACK` 任务。管理员取消任务时原子更新活动状态、释放租约，并由 Worker 心跳检测关闭当前 SSH channel。未知版本或损坏的执行快照必须以稳定错误码失败。

## 原因

- 仅使用进程内 `busy` 标记不能支持多个 Worker，也不能识别进程崩溃。
- 仅根据 `startedAt` 恢复任务会把正常的长时间构建误判为中断。
- Worker 离线时继续接受任务会制造长期排队且没有执行者的假成功操作。
- 数据库约束可以封闭 API 预检查后的并发竞争窗口。

## 兼容

没有租约信息的历史活动任务继续使用 `DEPLOY_WORKER_STALE_TIMEOUT_MS` 恢复；新任务只按租约过期判断。租约时长默认 30 秒，心跳周期为租约的三分之一。
