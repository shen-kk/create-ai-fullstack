# ADR-0017：Web 视觉设计由具体项目决定

## 状态

已接受，2026-09-07。

## 决策

模板不再规定具体品牌或审美风格。Web 端只提供可运行、可访问的中性 starter，以及稳定的工程边界：Nuxt SSR、Tailwind CSS、shadcn-vue 组件入口、状态反馈和可选动效分层。

颜色、字体、间距密度、圆角、阴影、图标语言、营销页结构和动画表达属于具体项目的产品设计。生成项目在开始正式页面开发前，应根据品牌与用户场景定义自己的 Web Token 和组件 variants；可以整体替换 starter 样式，不需要继承模板示例的视觉表达。

`project.config.json` 中的 `ui.web.designStandard` 使用 `project-defined`，表示该字段记录治理归属，不选择某个模板内置主题。项目名称、页面标题和页脚等品牌文案必须读取生成的项目声明，不得写死模板维护者的示例品牌。

生成项目通过 `docs/ai/WEB_DESIGN.md` 保存视觉确认状态。第一次进行 Web 页面或组件开发时，如果状态为 `pending`，AI 必须先请用户描述期望的样式风格；确认并记录为 `confirmed` 后才能开始界面实现。模板维护和不改变界面的工作不触发该门禁。

风格确认后的首次界面实现必须统一审计和调整全部现存 Web 界面、应用壳层、反馈组件、基础组件 variants、全局 Token 与动效，避免 starter 和项目设计并存。模板首页不得承担模板产品介绍或开发文档职责，只保留最小业务入口；主导航默认只有一个“首页”内容菜单。

## 原因

全栈模板可以复用工程能力与交互质量底线，但无法预先知道生成项目的品牌、行业、内容密度和目标用户。把某套审美写入 AI 规则和配置校验，会让后续实现误把示例样式当成不可变契约，并增加替换成本。

## 影响

- ADR-0009 中的 UI 与动效分层继续有效，其中指定 Apple、Linear、Vercel 视觉方向的决定由本 ADR 取代。
- 模板的 Web CSS 是 starter 实现，不是跨项目公共契约；业务行为、可访问性、SSR 和状态处理仍必须保留。
- 模板仍提供语义化 Design Token 接口，便于项目换肤，但不承诺某套 token 值或页面布局长期稳定。
- 首次视觉询问只在简报尚未确认时发生；后续开发复用已记录方向，避免每个任务重复打断用户。
- Admin 是内部运营界面，有独立规范，不受本次 Web 视觉归属调整影响。
