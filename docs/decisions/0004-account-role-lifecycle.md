# ADR-0004：管理员、角色与权限目录生命周期

- 状态：已接受
- 日期：2026-08-02

## 背景

后台模板必须提供安全、可审计且适用于多数项目的默认策略。直接删除管理员或角色会破坏历史审计语义；允许后台动态创建权限代码则容易造成前后端与数据库规则漂移。

## 决策

### 管理员账号

- 模板不提供管理员硬删除接口。
- 不再使用的账号通过状态改为 `disabled` 停用；审计日志和历史关联继续保留。
- 具体项目确需删除时，必须先在该项目领域文档中确定数据保留、个人信息清理和审计要求，再以独立 ADR 扩展。

### 角色

- 模板不提供角色删除接口。
- 系统角色不可修改；自定义角色可以清空权限并改名为“停用”，然后解除用户关联。
- 具体项目需要角色删除时，默认应拒绝删除仍被用户引用的角色，不允许静默级联解除授权。

### 权限目录

- 权限代码属于受版本控制的系统契约，不允许在后台动态创建、改名或删除。
- `packages/contracts/src/index.ts` 导出的 `permissionCatalog` 是权限目录的代码权威来源。
- 内存预览与 Prisma 种子共同消费此目录；数据库变更通过受审查的迁移/种子部署。
- 新增模块必须同时登记 `menu.<module>` 菜单权限和必要的 `<resource>.<verb>` 操作权限，并将操作权限应用于 API 守卫。

## 结果

- 审计记录不会因模板级删除功能失去主体语义。
- 新功能的权限定义可以由 AI 和代码审查一次性定位。
- 权限变更与代码版本同步发布，避免生产环境出现无法追踪的动态权限。
