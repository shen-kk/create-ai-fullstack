# ADR-0013：业务功能组合与环境初始化分离

## 状态

已接受。

## 背景

旧向导使用 quick、standard、custom 预设，同时询问业务功能、PostgreSQL、Redis 和服务商配置。邮件、短信和 Redis 被当作独立功能，但实际上被登录、找回密码、联系方式和通知等多个流程共享，容易出现裁剪一个消费者时误删共享实现的问题。模板维护者还可能走与生成项目不同的初始化路径。

## 决策

- `create-aiforge` 只询问是否启用用户端并组合代码，不收集运行凭据。
- 删除 quick、standard、custom 预设。
- PostgreSQL、端口、项目密钥和管理员由统一的 `pnpm run setup` 配置。
- 用户端账号整体包含验证码登录、找回密码、联系方式和头像上传流程；头像上传不作为独立选项。
- 部署中心、对象存储资源库、Git/服务器资源和 Deploy Worker 是平台基础能力，所有生成项目始终保留，不作为 CLI 选项。
- 邮件、短信、Redis 和具体服务商不作为 CLI 业务选项；启用用户端时自动保留其共享适配能力。
- 业务功能通过唯一功能目录声明依赖，`modules` 由依赖图生成。
- 模板维护者与普通用户使用相同的 setup、迁移、Doctor 和启动命令；区别仅是完整 Git 源码与 CLI 裁剪源码。
- 用户端未启用时物理删除 Web、用户身份 API 与对应后台页面；部署 Worker、部署中心、共享契约、迁移链和服务配置基础设施始终保留。

## 影响

- 新项目流程变为 `npm create aiforge` → `pnpm run setup` → `pnpm dev`。
- 服务资源可在项目启动后配置；功能未绑定资源时必须明确提示，不得默认选择第一条资源。
- CLI 交互只有一个“是否启用用户端”决策；功能目录只记录真正可裁剪的业务边界，不能把基础平台能力伪装成并列选项。
- 新功能不能通过散落的布尔判断接入，必须先登记功能 ID、依赖、归属路径和验证组合。
