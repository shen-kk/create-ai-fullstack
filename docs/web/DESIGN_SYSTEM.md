# Web 视觉系统边界

模板不提供必须继承的固定视觉风格。仓库中的页面和 CSS 是用于验证完整流程的中性 starter，不代表生成项目的品牌设计。具体项目应根据品牌、行业、内容和目标用户自行确定视觉方向；参见 ADR-0017。

## 项目开始时

- 首次页面或组件开发先读取 `docs/ai/WEB_DESIGN.md`；状态为 `pending` 时必须询问用户并记录确认结果，不得先做一版再让用户被动接受。
- 明确品牌语气、目标用户、内容密度、支持的设备和可访问性要求。
- 在正式扩展页面前定义项目自己的颜色、字体、间距、圆角、阴影、内容宽度和动效 Token。
- 可以修改或整体替换 starter 的页面布局和样式；不得因此破坏业务流程、SSR、键盘操作、可见焦点和状态反馈。
- 不把模板当前 CSS 的具体数值、营销页结构或装饰效果当作公共契约。
- 首次确认视觉方向后，统一审计并调整所有现存页面、壳层、反馈组件、基础组件 variants 和全局 Token；不允许只改新页面而留下混合视觉。
- 模板首页只承担最小业务入口，不展示模板能力、技术架构、安装命令或文档锚点导航；这些内容属于 README 与 `docs`。
- 导航中的同一目标只保留一个入口；登录与自动注册共用流程时使用一个清晰的账号操作，不同时展示“登录”和“开始使用”。

## Token

- 项目确定视觉方向后，颜色、字号、间距、圆角、阴影、内容宽度、层级和断点必须来自该项目的 Web Token。
- 页面不得随意增加接近但不同的颜色、圆角或阴影；新 Token 必须说明复用场景。
- 标题、正文、辅助文字和操作文字保持稳定层级，中文与英文混排需要检查视觉平衡。

## 交互

- Button、Input、Select、Dialog 等使用 shadcn-vue 公共组件。
- hover、focus、disabled、loading、error 状态都必须清晰且满足对比度。
- 手机端优先保证点击区域、输入体验、键盘遮挡和内容顺序。
- 全局反馈使用 AppToast，字段错误靠近控件；错误提示必须告诉用户下一步。
- 全局提示必须由业务结果显式指定语义：成功分支使用 `showSuccess`，异常分支使用 `showError`，普通说明使用 `showInfo`。禁止根据提示文案中的“失败”“错误”等关键词推断提示类型。
- 成功提示使用绿色与“操作成功”，错误提示使用红色与“操作未完成”，普通提示使用蓝色与“提示”；请求失败不得复用成功颜色或成功标题。
- 获取验证码按钮发送成功后，必须使用 API 返回的 `retryAfter` 展示逐秒倒计时并禁用按钮；当前浏览器会话刷新后倒计时仍应继续，不能通过刷新绕过重发限制。
- 验证码有效时间以 API 返回的 `expiresIn` 和后台认证设置为准，页面不得写死有效期。

## 响应式布局

- 桌面端的主从布局（例如个人中心左侧菜单、右侧内容）必须保持到 760px 以上，不能因为通用平板断点提前改成单列。
- 个人中心仅在视口宽度不超过 760px 时切换为单列；桌面窗口缩放与开发者工具停靠场景仍应优先保留左右结构。
- 全局 Header 使用粘性顶部定位；页面根容器不得使用会破坏 `position: sticky` 的纵向 `overflow: hidden/auto`。
