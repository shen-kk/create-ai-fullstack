# Web 新功能开发指南

1. 明确用户旅程、入口、退出路径、认证要求和 SEO 属性。
2. 新项目首次开发页面前检查 `docs/ai/WEB_DESIGN.md`；若为 `pending`，先询问用户期望的样式风格，记录为 `confirmed` 后再定义 Web Token，不得默认沿用模板 starter 的审美。
3. 第一次确认风格后，先审计所有既有 Web 页面、壳层、Toast、基础组件和全局样式，制定统一改造范围，不能只改本次新增页面。
4. 确认 API 与 contracts 已完成，不在 Web 复制服务端业务规则。
5. 先组合 `components/ui`，视觉增强再组合 `components/motion`。
6. 缺少基础组件时先补公共组件与状态示例，不在页面临时实现。
7. 覆盖首次加载、空态、错误、离线、会话过期、重复提交和成功反馈。
8. 验证 SSR 首屏、移动端、键盘操作、减少动态效果和中文排版。
9. 执行 `pnpm ui:check`、Web 类型检查、构建和相关测试。

营销展示与登录后业务区可以有不同页面密度；是否共享同一组视觉 Token 由具体项目决定，但同一产品区域内必须保持一致，基础交互组件仍使用统一入口。
