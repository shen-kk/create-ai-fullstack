# 用户领域

当前用户管理模块是模板中的查询与安全写入样板，用于演示“契约 → API → Admin → 测试”的完整链路。

## 术语与状态

- `active`：账号可正常使用。
- `disabled`：账号被管理员停用，不能登录。
- `pending`：账号已创建，尚未完成激活。

## 当前边界

- 查询支持关键词、状态和分页。
- 查询接口要求有效 Bearer Access Token，并必须具有 `users.read` 权限。
- 创建用户与状态变更要求 `users.write` 权限；前端按钮显示不能替代服务端守卫。
- 编辑姓名与邮箱同样要求 `users.write`；邮箱冲突返回稳定错误，密码和角色不通过基本资料接口修改。
- 角色使用稳定 `code` 标识；查看可分配角色要求 `roles.manage`，分配用户角色同时要求 `users.write` 与 `roles.manage`。
- Prisma 角色替换在事务中执行，提交的任一角色不存在时整体拒绝，不产生部分分配。
- 新用户邮箱规范化为小写，初始密码至少 6 个字符并只保存 scrypt 哈希，初始状态固定为 `pending`。
- 关键词匹配姓名或邮箱，不区分大小写。
- 用户查询通过 `UsersRepository` 隔离数据访问；运行时固定使用 PostgreSQL + Prisma，内存仓库只作为单元测试替身，不参与应用启动。
- 所有环境统一使用 PostgreSQL + Prisma，不提供示例数据源或运行时切换。
- 模板不提供管理员删除；账号退出使用时改为 `disabled`，保留审计和历史关联。具体项目确需删除时必须另行建立领域规则与 ADR。

## 持久化不变量

- 邮箱全局唯一，进入数据库前应规范化为小写。
- 密码只保存 `passwordHash`，任何查询 DTO 和日志都不得返回该字段。
- 用户状态使用数据库枚举；API 层负责映射为小写公共契约。
- 用户与角色、角色与权限都是显式多对多关系，不用逗号字符串保存。
- Refresh Session 保存脱敏设备信息，刷新令牌只保存摘要。管理员可以查看自己的有效设备并保留当前设备退出其他会话；Access Token 绑定 Session，Session 撤销后对应 Access Token 立即失效。
- 审计日志允许操作者删除后保留记录，因此 `actorId` 可为空。
