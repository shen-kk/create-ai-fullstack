# 冻结验收任务单

本文档是模板进入冻结版本前的唯一执行清单。执行人必须按任务编号顺序操作；每完成一项，就把状态从 `[ ]` 改为 `[x]`，并在“验收记录”填写日期、Git Commit、结果和证据位置。

冻结只表示当前通用能力和接口进入稳定维护，不表示以后不再增加业务功能。验收期间只修复阻断问题，不新增与冻结无关的功能。

## 0. 状态与规则

状态定义：

- `[ ]`：未开始。
- `[~]`：执行中。
- `[x]`：已通过。
- `[!]`：失败或阻断，必须记录原因，不能跳过后宣称冻结完成。
- `[N/A]`：当前模板明确不承诺的能力，必须记录排除理由。

验收证据不得包含 `.env`、数据库连接串、密码、Token、SSH 私钥、Cookie 或服务密钥。日志中发现密钥时，应先删除证据并修复脱敏问题。

### 外部环境使用规则

- 模板源仓库不得预设或主动连接本地 PostgreSQL、Redis、SSH、对象存储、短信、邮件、支付或 Deploy Agent 环境。
- 不得为了让验收显示“通过”而临时搭建、伪造或替代外部服务。
- 只依赖纯代码的契约、校验、单元测试和内存模式可以由 AI 直接执行。
- 需要真实数据库、SSH、CNB、Docker、域名或第三方服务时，任务状态保持“等待环境”，由项目所有者提供测试配置后再验收。
- AI 请求环境时必须一次列出用途、必填字段、网络要求和安全保存位置；不得要求用户把密钥提交到 Git 或聊天记录。

每轮验收先记录候选版本：

```text
候选 Commit：待填写
执行日期：待填写
执行人：待填写
操作系统：待填写
Node / pnpm 版本：待填写
```

- [ ] FZ-010 `pnpm install --frozen-lockfile` 通过。

执行命令：

```bash
pnpm install --frozen-lockfile
pnpm template:doctor
pnpm check
pnpm test:e2e
pnpm template:verify -- --full
node --check tools/deploy-agent/agent.mjs
node --check tools/deploy-agent/doctor.mjs
```

在 CI 或其他非交互终端执行 pnpm 时先设置 `CI=true`。源模板不提交 `.env`，因此源目录 Doctor
允许且只允许“缺少 `.env`”这一项失败；全新初始化项目中的命令退出码必须全部为 0。其余命令不得出现未处理警告、测试跳过或依赖锁文件变化。Deploy Agent Doctor 可在缺少必填变量时明确失败，并在配置正确时通过。
